# Aetheria

Aetheria 是一个基于 **Flutter + Rust** 构建的跨平台（Windows / Linux / Android）本地音乐库与高保真播放器。应用以 **Flutter UI + Provider 状态层 + `flutter_rust_bridge` + Rust 曲库/音频核心 + 平台原生通道** 分层组织，围绕“多音源版本管理、精细化分类整理、原汁原味的音频还原与特殊场景扩展”设计了一系列专用机制。

---

## 核心功能与特殊机制

### 一、托管曲库与「多音源版本」模型

Aetheria 采用统一托管目录管理所有音乐资产，而不是松散地引用外部散落路径：

- **短生命周期 WAL 连接策略**：每次数据库调用均开启 `WAL` + 外键约束，并在操作结束后立即释放连接句柄，避免长连接持锁影响局域网整库热替换。
- **严谨探测与去重**：支持 `mp3` / `wav` / `flac` / `m4a` / `ogg` / `aac` 导入。使用 `lofty` 读取标签并结合 `symphonia` 估算真实时长（针对容器元数据不可靠的原始 `.aac` 做专门扫描），对超长垃圾内嵌标签（如异常 `[awlrc:]`、`[kana:]`）进行清洗；入库前计算全文件 MD5，杜绝同库重复导入。
- **一等公民级多音源版本（`AudioVersion`）**：同一首歌曲可以挂接多个独立音频版本（如无损母带、Live 版、修复版、伴奏版等）：
  - 支持随时指定或切换 **默认播放版本**，正在播放当前歌曲时切版本会尽量维持原有播放位置。
  - 删除默认版本后自动将剩余最早版本晋升为默认版本；删除整首歌曲会联动清除所有关联版本文件、旁路 `.lrc`、封面与表记录。
  - 支持单个物理音源版本的独立导出与删除。

### 二、歌单管理与「导入自动归属」

- **一致的排序规则**：非歌单视图（如「全部歌曲」）在全平台使用纯 Dart 实现的 **Explorer 风格自然排序**（例如 `Track 2` 排在 `Track 10` 之前，桌面端与移动端排序结果完全一致）；进入任意常规歌单后则严格保持用户自定义的排序顺序。
- **跨歌单整理**：桌面端支持多选、连续范围选与鼠标框选，支持跨歌单复制、剪切与粘贴排序。
- **导入默认归属当前歌单**：在选中某个歌单的状态下触发单文件或整文件夹导入（支持批量元数据预览勾选），新入库及匹配挂载的歌曲会按导入顺序自动加入当前激活的歌单；批量导入时单个文件失败不会中断其余文件，结束后统一汇报成功数与失败原因。

### 三、标签体系：三态过滤、双层优先级与纵向对齐

- **三态循环过滤**：点击顶部标签可在 `未选 → 正向包含 → 反向排除 → 未选` 间循环切换，结合 `AND / OR` 模式完成高精度交叉筛选。
- **分类与标签双层自定义优先级**：支持为标签 **分类**（流派、语言、情绪、场景及自定义分类）单独分配显示顺序，同时支持调整每个分类内部各个 **标签** 的优先级。歌曲列表、筛选栏与编辑器均统一按照「先分类优先级、再类内标签优先级」渲染，且该配置可随局域网同步迁移到其他设备。
- **歌曲表「标签对齐模式」**：开启对齐模式后，系统会在当前列表渲染前预扫描每个标签分类在单首歌曲上同时出现的最大数量，并在表格标签列中为各分类预留固定宽度与竖向槽位；当某首歌曲缺少该分类标签时自动保留对应空位，从而让同一类标签在整张长列表中严格纵向对齐。

### 四、Phigros 专区与实时采样级打击音效引擎

Aetheria 内置专门面向音游 **Phigros** 的扩展专区，可将解包曲库直接还原为带真实打击音效且可切换难度的可播放曲目：

- **资产解包与防碰撞入库**：配套的 `scripts/extract_phigros.py` 可从 Phigros APK / OBB 提取无损 FLAC 音轨、曲绘、章节元信息、官方打击音效（Tap/Hold 头判、Drag、Flick）与各难度谱面时间线；针对含非 ASCII 字符曲目 ID 自动生成哈希防碰撞命名，并通过单事务原子写入独立 `kind = 'phigros'` 专区歌单（支持按章节筛选，同时保留在全库中进行搜索、标签管理与局域网同步的能力）。
- **采样帧级实时打击音效混音（`HitSoundMixer`）**：
  - 在 Rust `DecodePipeline` 内（变调处理之后、整曲增益和峰值保护之前）将解码重采样后的官方音效按输出采样帧精确混入主音频流。
  - 自动在 `2.5 ms` 窗口内合并同音色多押音符避免线性叠加削波，限制并发尾音数量并完整保留跨音频块尾音衰减，Seek 或暂停恢复时自动清理重同步。
- **双层调控与多难度热切**：支持即时切换 `EZ / HD / IN / AT / SP / Legacy` 等全难度谱面（兼容部分曲目特定难度的专属音频或专属曲绘覆写），展示谱师、BPM 范围、定数、总物量与四类音符占比；同时支持 **全局** 与 **单曲级**（`跟随全局 / 强制开启 / 强制关闭` + 独立音量与毫秒偏移）热调节，播放过程中调整参数实时生效。

### 五、高保真 Rust 音频管线与专用 DSP 机制

播放链路完全由 Rust 原生引擎接管，通过 `cpal` 直接输出至系统设备：

- **全链路 64-bit 浮点处理与无损输出协商**：`symphonia` 解码后以 `f64` 执行 DSP 运算，末尾依次经过软限幅峰值保护（超出满刻度时平缓压限并记录削波统计）和针对整数硬件输出的 **TPDF（三角概率密度）微抖动** 降噪；输出端按声道配置与源采样率、位深由高到低协商最优设备格式。
- **主动响度均衡（只降不升）**：导入时按 BS.1770 对全曲测量综合响度。满强度以 −16 LUFS 为参考，每秒评估一个 3 秒短时窗口，按持续偏响的程度额外衰减最多 3 dB。播放器对整首使用固定增益，旧库启动后会在后台逐首补测。
- **实时音调调节与「仅人声升降调」**：支持无须重建播放流的 **Rubber Band LiveShifter**（提供共振峰保留与窗函数选项）及重采样变调两种模式；开启「仅人声升降调」时，实时拆解立体声的 Mid（中置）与 Side（侧置）分量，仅对中置人声做音高变换并对齐延迟尾帧，尽量无损保留左右声道伴奏氛围。
- **硬件消耗帧校准与引擎剖析**：播放进度直接由音频硬件回调累计的消费采样帧推算，不受缓冲大小和 Rubber Band 处理延迟漂移影响；开发者模式内置调用树耗时统计、输出缓冲区水位、真实峰值与 Underrun 报告导出。

### 六、双作用域歌词、逐字插值与跨平台悬浮歌词

- **歌曲级与版本级双作用域歌词**：导入音频时自动提取并入库内嵌歌词，支持旁路 `.lrc` 复制及多源在线检索（网易云音乐、QQ 音乐、酷狗音乐、LRCLIB），并允许把歌词精细绑定到「整首歌曲」或「某一特定音源版本」。
- **多格式解析与点击跳转**：兼容普通 LRC、QRC 逐字时间轴、双语翻译与罗马音；支持在歌词面板中滚动预览并点击任意一行直接跳转到对应时间播放。
- **平滑时间锚点插值与多端呈现**：
  - 在低频跨 FFI 进度同步之间使用单调时钟插值估算当前毫秒时间，以高帧率顺滑驱动逐字歌词进度。
  - **Windows**：原生透明置顶桌面悬浮歌词窗口。
  - **Linux**：Wayland 桌面优先使用 `gtk-layer-shell` 独立 Overlay 层与鼠标穿透渲染（X11 自动回退普通透明浮窗）。
  - **Android**：支持系统悬浮窗、MediaSession / 通知栏播放控制，并可选接入 **SuperLyricApi** 将逐行、逐字与翻译歌词直推至状态栏模块显示。

### 七、Linux 桌面高刷直出与长列表流畅交互优化

- **定制 Linux 渲染与线程分离机制**：Linux Runner 默认将 Dart UI 线程与 GTK 平台输入线程分离，并在 Wayland 下通过定制引擎（`linux/engine/`）经独立异步 `wl_subsurface` + EGL window surface 直接提交帧画面，避开每帧 GTK/Cairo 整窗重绘（支持通过 `AETHERIA_DIRECT_WAYLAND=0` 与 `AETHERIA_UI_THREAD=platform` 对比切换）；默认采用 Skia 渲染规避 NVIDIA + Wayland 下实验性 GLES Impeller 的 FBO 异常与假死（可通过 `AETHERIA_ENABLE_IMPELLER=1` 主动开启），关闭主窗口时经 `_exit()` 同步退出确保进程安全回收。
- **桌面歌曲表高性能交互**：表格内置独立的文本布局缓存（`SongTableTextCache` 与自定义 `RenderBox`），减少滚动过程中的重复排版开销；鼠标滚轮采用单条可中断 Ticker 动态接管并保持连贯速度，拖动滚动条与触控滑动保持 1:1 零延迟直跟。

### 八、局域网整库镜像同步

面向 PC / 移动端之间免数据线迁移与镜像整库设计：

- **自动发现与审批授权**：通过 UDP `43871` 广播自动发现同局域网设备（Android 自动持有 MulticastLock），配合临时随机端口 HTTP 服务通信；拉取前必须由源设备人工确认并发放临时授权 Token 后才开放 `/sync/manifest`、`/sync/database` 与 `/sync/file`。
- **增量快比与事务级原子回滚**：拉取端先基于「相对路径 + 文件大小」快速筛选新增、改动与多余文件，下载后逐一校对 MD5 完整性；同步范围涵盖 `database.db`、全部托管音频（`files/`）、封面（`covers/`）、Phigros 谱面与音效（`phigros/`）以及标签优先级配置。同步过程先落盘至 `.sync_tmp/`、将本机原文件移至 `sync_backups/`，确认全量无误后再执行原子替换与陈旧文件裁剪；任一步骤出错自动完整回滚，并在校验敏感阶段防止错误写入破坏本地曲库。
