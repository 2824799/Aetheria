# Aetheria

一个以 `Flutter + Rust` 为核心技术栈构建的本地音乐播放器与音乐库管理应用，重点面向 Windows 桌面端与 Android 移动端。Aetheria 不只是“能播放歌”，而是把音乐文件托管、音源版本管理、歌词检索与绑定、悬浮歌词、局域网镜像同步、标签过滤、歌单管理、音频 DSP 调整等能力整合在了一套统一界面里。

当前仓库已经从早期的前端方案重构为 `Flutter UI + Rust 数据/音频引擎` 架构，核心数据通过 SQLite 管理，Flutter 与 Rust 之间通过 `flutter_rust_bridge (FRB v2)` 通信，原生平台能力通过 Android Kotlin 与 Windows C++ 补充。

## 项目定位

Aetheria 适合下面这类使用场景：

- 想把零散的本地音乐文件整理成可维护的托管音乐库。
- 同一首歌可能拥有多个音源版本，希望明确设置“默认播放版本”。
- 需要把歌词绑定到具体歌曲，甚至绑定到具体音源版本。
- 希望在桌面或手机上使用高可定制的悬浮歌词。
- 有多台设备，想在局域网内把音乐库完整同步到另一台设备。
- 希望用更原生、更可控的 Rust 音频链路来做播放、音高调整和输出质量控制。

## 当前支持情况

| 项目 | 状态 |
| --- | --- |
| Windows 桌面端 | 重点支持 |
| Android 移动端 | 重点支持 |
| Android 构建目标 | 当前以 `arm64-v8a` 为主 |

## 功能总览

下面这部分按照“用户实际能做什么”来梳理当前代码已经实现的主要能力。

### 1. 音乐库与文件托管

- 自定义音乐库根目录，首次启动默认落在应用文档目录下。
- 音乐文件导入后会被托管到库内，而不是直接依赖原始散落路径。
- 支持单文件、多文件导入。
- 支持整文件夹扫描导入。
- 文件夹导入前会先读取候选文件元数据，给出导入预览列表，并允许用户勾选要导入的条目。
- 支持的音频格式包括 `mp3`、`wav`、`flac`、`m4a`、`ogg`、`aac`。
- Rust 端会读取音频元数据，包括标题、歌手、专辑、时长、比特率、采样率、位深、文件大小等。
- 导入时会计算音频 MD5，避免重复导入同一物理音频。
- 会尽量提取音频文件中的内嵌封面，并缓存为可复用的封面文件。
- 如果源文件旁边存在同名 `.lrc`，导入时会一起复制到托管库。
- 支持把一个新音频文件“关联”为已有歌曲的新音源版本，而不是总是新建歌曲。
- 支持导出某个音源版本的物理文件。
- 支持删除整首歌曲，删除时会同时清理数据库记录、本地托管音频文件、关联歌词与封面。
- 支持只删除某个音源版本；如果删掉的是默认版本，会自动把剩余版本中的一个补成默认版本。
- 支持“重置音乐库”，会清空核心表、重建托管文件目录并重新写入默认标签种子数据。

### 2. 音乐库浏览、检索与组织

- 左侧边栏提供“全部歌曲”与“歌单”两大导航入口。
- 支持新建、重命名、删除歌单。
- 歌单删除不会删除音乐文件本身。
- 支持将歌曲加入歌单。
- 支持从歌单中移除歌曲。
- 支持歌单内的复制、剪切、粘贴式操作流。
- 搜索框可按歌曲名、歌手、专辑模糊过滤。
- 标签过滤器支持两种匹配模式：
  - `AND / 全部包含`
  - `OR / 任意包含`
- 标签支持三态筛选：
  - 未参与过滤
  - 正向包含
  - 反向排除
- 过滤结果会实时作用到歌曲表。
- 歌曲列表支持按当前歌单顺序展示。

### 3. 歌曲表与交互细节

- 自定义歌曲表头，当前包含：
  - 歌曲名称
  - 歌手
  - 标签
  - 版本数
  - 默认音质
- 表头支持拖拽重排列顺序。
- 表头支持拖拽改变列宽。
- 列顺序与列宽会持久化保存到本地设置。
- 支持单选、多选、`Ctrl / Cmd` 追加选择、`Shift` 范围选择。
- 支持鼠标框选多首歌曲。
- 支持右键上下文菜单。
- 右键菜单当前可执行：
  - 复制所选歌曲
  - 剪切所选歌曲
  - 从当前歌单移除
  - 添加到任意歌单
  - 粘贴到当前歌单
  - 彻底删除歌曲
- 双击歌曲可直接开始播放。
- 单击歌曲会激活详情面板。
- 表格中会用 `LRC` 标记提示歌曲是否已存在可用歌词。

### 4. 标签系统

- 标签有独立定义表，可复用绑定到多首歌曲。
- 标签支持名称、颜色、分类。
- 内置默认分类思路包括语言、流派、情绪等。
- 可新建自定义标签。
- 可编辑已有标签。
- 可删除标签。
- 在歌曲详情页中可以直接勾选或取消勾选标签绑定。
- 标签过滤区支持折叠/展开。
- 在桌面布局中提供独立标签管理弹窗。

### 5. 歌词系统

歌词是这个项目里比较完整的一块，除了显示，还包含搜索、保存、绑定、偏移、翻译与悬浮输出。

- 歌词既可以绑定到“歌曲”，也可以更精确地绑定到“具体音源版本”。
- 支持读取本地歌词候选：
  - 音频内嵌歌词
  - 同名本地 `.lrc`
  - 旧版歌曲字段里的遗留歌词
- 支持在线歌词检索来源：
  - `LRCLIB`
  - `网易云音乐`
  - `QQ 音乐`
  - `酷狗音乐`
- 支持手动粘贴歌词并保存到当前歌曲/当前音源版本。
- 支持保存翻译歌词与罗马音字段。
- 支持歌词偏移量调整（毫秒级）。
- 支持从当前歌词预览中一键复制文本。
- 歌词显示页支持滚动高亮。
- 支持解析常见时间轴歌词格式。
- 支持解析带翻译行的同步歌词。
- 在歌词滚动界面里，用户滚动到某一行后可直接从该行时间点开始播放。
- 如果当前歌曲没有歌词，可直接跳转到歌词管理界面。
- 歌词保存成功后，歌曲列表中的歌词标记会同步刷新。

### 6. 悬浮歌词

这是项目的特色能力之一，且 Windows 与 Android 都做了原生适配。

- 支持开启/关闭悬浮歌词。
- 支持锁定悬浮窗，锁定后不再响应拖拽。
- 支持始终置顶。
- 支持暂停时淡出显示。
- 支持显示翻译。
- 支持显示下一句歌词。
- 支持紧凑多行模式，可额外显示更多后续上下文行。
- 支持当前行加粗。
- 支持当前行放大。
- 支持文字阴影。
- 支持左对齐、居中、右对齐。
- 支持字体大小、行间距、透明度调整。
- 支持未播放颜色、已播放颜色、阴影颜色自定义。
- 支持刷新帧率调整。
- 支持记忆悬浮窗的位置与尺寸。
- 支持重置悬浮窗尺寸位置。
- Android 端通过前台服务 + 系统悬浮窗权限实现。
- Windows 端通过单独的透明分层窗口实现，可拖拽、可缩放，并向 Flutter 回传窗口位置变化。

### 7. 播放控制

- 基于 Rust 原生音频链路播放，不依赖 Flutter 纯 Dart 播放方案作为主核心。
- 支持播放、暂停、上一首、下一首。
- 支持拖动播放进度条。
- 支持队列连续播放。
- 支持三种播放模式：
  - 列表循环
  - 随机播放
  - 单曲循环
- 支持音量调节。
- 支持播放状态恢复：
  - 上次播放歌曲
  - 上次播放音源版本
  - 上次播放位置
  - 上次队列顺序
  - 上次音量
- 应用启动后会尝试恢复之前的播放上下文，但默认不会自动开始播放。
- 在 Windows 等桌面平台上会检测默认输出设备变化，必要时自动重建当前播放，尽量跟随系统默认输出切换。

### 8. 音频处理与 DSP 选项

当前播放器不仅能播，还能调。

- 支持音高调整（半音级别）。
- 支持至少两类音高处理思路：
  - `rubberband`
  - `resample`
- 支持输出处理缓冲大小调整。
- 支持输出延迟模式：
  - `shared-default`
  - `shared-low-latency`
  - `shared-stable`
- 支持音量平衡/响度归一思路：基于队列中音源响度计算增益，减轻歌与歌之间响度突变。
- 支持峰值保护，防止后处理后爆音。
- 支持抖动（dither）。
- 对 `Rubber Band` 处理可设置窗口偏向：
  - `latency`
  - `quality`
- 支持 formant 保持开关。
- 支持重采样质量设置：
  - `standard`
  - `high`
- 调整大部分音频参数后，会对当前播放进行热重载，尽量不中断用户体验。
- 设置面板会实时展示原生输出信息，例如：
  - 当前输出设备名
  - 采样率
  - 声道数
  - 采样格式
  - 队列缓冲长度
  - 设备缓冲配置
  - 延迟模式
  - 峰值
  - 剪裁保护计数
  - 输出欠载次数

### 9. 音源版本管理

这个项目把“同一首歌的不同文件版本”作为一等公民来管理。

- 每首歌可挂多个音源版本。
- 每个版本保存独立的格式、时长、比特率、采样率、位深、响度等信息。
- 可指定某个版本为默认播放版本。
- 如果歌曲正在播放，切换默认版本时会尽量保持当前播放进度并切过去。
- 支持导出单个版本文件。
- 支持删除单个版本。
- 支持手动补充一个新的版本文件并挂到现有歌曲下。
- 支持标记某个版本是否已经完成完整元数据扫描。
- 支持对整个库或仅未完整扫描版本执行刷新扫描。

### 10. 局域网同步

局域网同步不是“云盘式合并”，而是更偏向“镜像覆盖同步”。

- 设备启动后可自动开启局域网发现服务。
- 使用 UDP 广播发现同网段中的其他 Aetheria 设备。
- 每台设备会广播：
  - 设备 ID
  - 设备名称
  - HTTP 服务端口
  - 歌曲数
  - 版本数
- 发现到设备后，界面里可以直接看到可同步目标。
- 发起同步时，对端需要显式审批。
- 审批通过后，会为本次同步生成带过期时间的临时授权 token。
- 同步过程会拉取对端：
  - `database.db`
  - `files` 目录中的托管音频文件
- 会先读取远端 manifest，再按需下载缺失或发生变化的文件。
- 支持通过文件大小与 MD5 进行校验。
- 同步前会自动暂停本机播放。
- 同步前会自动备份本机库。
- 同步完成后会重新初始化本地库并刷新界面。
- 当前同步策略是“对方为准的镜像覆盖”：
  - 对方有、本机没有：下载到本机
  - 对方没有、本机有：本机会删除对应文件和数据
- 当前不会同步本机偏好设置，例如：
  - 主题
  - 悬浮歌词样式
  - 音频 DSP 设置
- 本地同步状态、进度与错误信息都会在设置面板中显示。

### 11. 设置与个性化

- 内置三套主题：
  - `Dark`
  - `Light`
  - `Pink`
- 主题会持久化保存。
- 设置面板按功能分区，当前主要包括：
  - 个性外观
  - 播放设置
  - 桌面歌词
  - 音乐库管理
  - 局域网同步
- 可在设置中切换托管音乐库路径。
- 可在设置中导入文件或整个文件夹。
- 可在设置中触发库刷新或重置。

### 12. Android 原生能力

- 播放通知栏支持上一首、播放/暂停、下一首。
- 通知栏支持显示进度与总时长。
- 通知栏可读取当前音频内嵌封面并显示大图。
- 通过 `MediaSession` 对接系统媒体控制。
- 支持从通知操作回调到 Flutter 侧控制播放。
- 可申请通知权限。
- 可申请悬浮窗权限。
- 可获取设备名，便于局域网同步时识别。
- 可申请与释放 Wi-Fi Multicast Lock，提升局域网广播发现稳定性。
- 可把音源文件导出到系统 `Downloads/Aetheria` 目录。
- 启动时会尽可能请求更高刷新率显示模式。

### 13. Windows 原生能力

- 使用单独的透明窗口承载悬浮歌词。
- 支持拖拽移动与边缘缩放。
- 支持置顶与穿透切换。
- 使用 GDI+ 绘制文本、阴影与进度填充。
- 会把悬浮窗新边界回传给 Flutter，用于持久化位置与尺寸。

## 技术架构

### 总体架构

```text
Flutter UI
  ├─ Provider 状态层
  ├─ 文件选择 / 本地设置 / 页面交互
  ├─ 歌词显示、歌单、标签、设置、同步 UI
  └─ 通过 flutter_rust_bridge 调用 Rust API

Rust Core
  ├─ SQLite 数据库
  ├─ 音乐导入 / 元数据解析 / 封面提取
  ├─ 歌词数据持久化
  ├─ 局域网同步协议配合
  ├─ 音频播放 / 解码 / DSP / 输出设备管理
  └─ 向 Dart 暴露桥接接口

Native Platform Layer
  ├─ Android Kotlin
  │  ├─ 通知栏控制
  │  ├─ 悬浮歌词 Service
  │  ├─ Downloads 导出
  │  └─ Multicast / 权限
  └─ Windows C++
     └─ 悬浮歌词透明窗口
```

### 关键技术选型

#### Flutter 侧

- `provider`：状态管理
- `shared_preferences`：本地偏好设置与播放状态持久化
- `file_picker`：文件/文件夹选择
- `path_provider`：应用文档目录
- `flutter_rust_bridge`：Flutter 与 Rust 的 FFI 桥接

#### Rust 侧

- `rusqlite`：SQLite 数据库存储
- `lofty`：音频标签与元数据读取
- `symphonia`：音频解析与更可靠时长估算
- `cpal`：跨平台音频输出
- `rubberband`：音高/时域处理
- `uuid`：业务主键
- `md5`：文件去重与同步校验

## 数据目录与存储说明

音乐库初始化后，根目录下通常会出现类似结构：

```text
<library_path>/
├─ database.db          SQLite 主数据库
├─ files/               托管音频文件
├─ covers/              提取出的歌曲封面
├─ sync_backups/        局域网同步前自动生成的备份
└─ .sync_tmp/           同步过程中的临时目录
```

### 数据库存储的核心实体

当前主要表如下：

- `songs`
  - 歌曲基础信息
  - 标题、歌手、专辑、遗留歌词字段、封面路径、评分、时间戳
- `audio_files`
  - 歌曲的音源版本
  - 文件路径、原始文件名、格式、比特率、采样率、时长、位深、响度、是否默认版本、是否完成完整扫描
- `tags`
  - 标签定义
- `song_tags`
  - 歌曲与标签的多对多关系
- `lyrics`
  - 歌词内容
  - 支持绑定到歌曲，或更精确地绑定到某个音源版本
- `playlists`
  - 歌单定义
- `playlist_songs`
  - 歌单与歌曲关系，并带有排序字段

### 默认种子标签

库初始化或重置后，会自动写入一批默认标签，例如：

- 语言：中文、英文、日韩
- 流派：纯音乐、摇滚、流行、民谣、古典
- 情绪：伤感、治愈、欢快

## 快速开始

### 环境要求

建议准备以下开发环境：

- Flutter SDK
- Dart SDK `^3.12.2`
- Rust stable toolchain
- Android Studio / Android SDK（如果需要打 Android 包）
- Visual Studio 2022 C++ 桌面开发工具链（如果需要构建 Windows）
- CMake / Ninja（通常由 Flutter Windows 工具链配套）

### 1. 获取依赖

```bash
flutter pub get
```

如果本机尚未安装 Rust：

```bash
rustup default stable
```

### 2. 运行 Windows 桌面版

```bash
flutter run -d windows
```

### 3. 运行 Android 版本

```bash
flutter run -d android
```

### 4. Windows 打包

```bash
flutter build windows
```

默认输出位置：

```text
build/windows/x64/runner/Release/aetheria.exe
```

注意：运行最终产物时，需要保证同目录下的依赖 DLL 保持完整。

### 5. Android 打包

```bash
flutter build apk --target-platform android-arm64
```

默认输出位置：


## 首次使用建议流程

### 1. 首次启动

- 应用会初始化 Rust 库与本地数据库。
- 如果此前保存过库路径，会直接使用保存的路径。
- 如果没有保存过，则默认使用应用文档目录作为库根目录。

### 2. 导入音乐

推荐二选一：

- 从“导入歌曲”直接选择多个音频文件。
- 从“导入歌曲”选择整个文件夹，先预览、再勾选、再批量导入。

### 3. 整理歌曲

- 给歌曲打标签。
- 创建歌单。
- 对同一首歌补充不同音源版本。
- 为想长期使用的版本指定“默认播放版本”。

### 4. 补齐歌词

- 在详情面板切到“歌词管理”。
- 先尝试自动搜索。
- 如果线上源不满意，可手动粘贴。
- 若歌词与音频不同步，再调整偏移。

### 5. 开启悬浮歌词

- 在设置中打开桌面歌词。
- Android 首次使用时，需要允许悬浮窗权限。
- Windows 端可直接拖动或缩放悬浮窗。

### 6. 使用局域网同步

- 确保两台设备都在同一局域网。
- 双方都打开 Aetheria。
- 在设置的同步页面刷新发现设备。
- 从目标设备拉取时，对端会收到授权弹窗。
- 阅读覆盖提示后再确认执行，因为当前是镜像覆盖同步。

## 开发说明

### Flutter 与 Rust 桥接

Rust 对 Flutter 暴露的主要接口集中在：

```text
rust/src/api/music.rs
```

如果你修改了 Rust 暴露函数、参数或返回值，记得重新生成 FRB 代码。当前仓库的约定是：

```bash
flutter_rust_bridge_codegen
```

随后再执行：

```bash
flutter pub get
```

必要时重新构建对应平台。

### 关键 Provider

Flutter 侧几个最核心的状态模块：

- `UIThemeProvider`
  - 主题系统与主题持久化
- `LibraryProvider`
  - 歌曲、标签、歌单、库路径、搜索与过滤、导入删除、元数据刷新
- `AudioPlayerProvider`
  - 播放控制、队列、播放状态恢复、DSP 参数、原生输出信息
- `FloatingLyricsProvider`
  - 悬浮歌词样式、位置、尺寸与偏好
- `SyncProvider`
  - 设备发现、局域网同步、授权、拉取进度与错误

### Android 构建特别说明

仓库里对 `android/build.gradle.kts` 做了兼容性处理，用于强制相关子工程使用较新的 `compileSdkVersion`。这是为了避免某些插件在 Android 构建时因为 SDK 版本过低而报错。

如果你遇到 Android 构建突然在 AAR Metadata 检查阶段失败，先检查这段兼容逻辑是否被改动或删除。

### 音频时长与元数据扫描

项目在导入和刷新阶段会尽量保证时长信息可靠：

- 先尝试使用 `lofty`
- 不可靠时回退到 `symphonia`
- 某些原始 AAC 场景会走特殊时长估算逻辑

这也是为什么项目里会有“刷新数据库 / 仅刷新未完整扫描歌曲”的能力。

## 常见问题

### 1. 为什么启动后是空库？

因为 Aetheria 维护的是自己的托管音乐库。首次启动时没有导入任何歌曲，数据库自然为空。先导入文件或文件夹即可。

### 2. 为什么局域网同步后本机部分歌曲消失了？

因为当前同步策略是镜像覆盖，对端没有而本机有的内容会被删除。同步前会自动备份，但仍建议把这当成一次“以对方为准”的覆盖操作。

### 3. 为什么悬浮歌词在 Android 上不显示？

通常是因为还没有授予悬浮窗权限，或者系统限制了前台服务显示。请先在系统设置里确认 `SYSTEM_ALERT_WINDOW` 相关权限是否已打开。

### 4. 为什么有些歌曲显示“待完整扫描”？

说明该版本的响度、位深或部分音频元数据还没有完成完整刷新。可在设置中执行库刷新。

### 5. 为什么改了 Rust 接口后 Dart 调用报错？

大概率是 FRB 生成代码还没同步更新。重新运行 `flutter_rust_bridge_codegen` 并重新构建。

## 已知限制与当前边界

- 当前重点支持平台是 Windows 与 Android。
- 局域网同步目前是“整库镜像覆盖”，不是细粒度双向合并。
- 没有完整的云端账户体系或在线曲库能力。
- 在线歌词检索依赖第三方服务返回结果，稳定性受外部接口影响。
- 项目已包含测试脚手架，但自动化覆盖率并不代表已经覆盖所有复杂交互场景。
