# UI 交互与性能排查 · 2026-10-07

这次覆盖公共按钮、弹层、菜单、底部面板、曲库列表、桌面详情抽屉、移动端抽屉和迷你播放器，以及播放进度、歌词和封面更新链路。下列问题已修复并保留回归测试。尚未完成 Android / Windows 真机和真实音频负载下的帧率对比，不能据此认定所有设备上的卡顿均已消除。

## 修复记录

| 问题 | 原因与处理 |
| --- | --- |
| 播放时设置页、详情页和播放器反复重建 | 原来的 250 ms 进度轮询广播整个 AudioPlayerProvider；改为独立的 positionListenable，仅时间、进度和歌词订阅。歌词只在当前行变化时重建。 |
| 移动端滚动拖累整页 | 标签折叠在每次滚动时 setState 整个页面，触发曲库筛选和排序；改为局部 ValueNotifier，直接应用折叠高度，取消叠加的尺寸动画。 |
| 频繁重复排序，大歌单成本高 | displaySongs 每次读取都复制、筛选和排序；现在复用只读结果，通知状态变更时失效。歌单使用 ID 映射按顺序取歌曲，替代排序比较器中的线性 indexOf。 |
| 歌单切换反馈迟缓或快速切换后串单 | 先发布新选择并清空旧列表，使用请求序号丢弃过时的异步响应。 |
| 按钮按下反馈迟缓、焦点边框扰动尺寸 | 原来等待 tap 手势判定才显示按压；改用指针事件立即反馈，滚动超出手势容差后取消反馈，业务动作仍由手势识别触发。高亮和焦点边框改为前景绘制。 |
| 进度条拖动反复调用音频引擎 | 拖动时局部预览，松手提交一次 seek；等待结果期间保留预览，并避免旧请求清除新拖动的预览。桌面进度条置于播放器内容上层，保持整个命中区域可用。 |
| 移动端迷你播放器盖住抽屉遮罩 | 将播放器移到 Scaffold 的 body 内，抽屉与遮罩自然位于其上层。 |
| 桌面详情关闭后仍保留隐藏子树 | 动画完全退出时卸载抽屉与遮罩；静态内容通过 AnimatedBuilder.child 复用，列表和面板分别隔离重绘。主布局只订阅加载状态和待处理同步请求。 |
| 长菜单溢出、小面板挡住外部点击 | 菜单约束扣除安全区与键盘，长内容可滚动；底部面板按内容收缩并使用安全区，外部区域交还模态遮罩。 |
| 阴影被裁切、玻璃面板合成成本高 | 阴影移到圆角裁切外；玻璃前景单独隔离重绘。Linux 公共玻璃面板采用实色合成，延续原详情面板的 Linux 处理；零模糊及减少动画设置跳过背景模糊。 |
| 小屏标签控制项横向溢出 | 顶部控制项允许换行；回归覆盖 320 逻辑像素宽的移动布局。 |
| 封面阻塞 UI 或快速切歌显示旧图 | 移除 build 内同步文件检查，异步检查和加载，按显示尺寸解码，用请求序号和歌曲 ID 防止旧结果覆盖。 |
| 不必要的后台工作与叠加请求 | 每秒只持久化播放位置，不再重复保存整条队列；播放位置轮询和悬浮歌词更新防止请求重叠。悬浮歌词关闭时停止计时器，开启后按刷新率调度，暂停后降至 500 ms。 |
| 反复弹窗及通知的资源生命周期 | 路由曲线改为无独立监听生命周期的 CurveTween；Toast 替换时释放 OverlayEntry，旧退出回调不能移除新通知。 |

## Profile 采样

环境：本机 Linux x64 / Fedora 44，Flutter 3.47.0，Profile 模式。每个场景装载 5000 首合成歌曲，交替执行 12 次、每次 400 ms 的滚动，同时以 250 ms 周期模拟播放进度。移动布局同样运行于 Linux，不能代表 Android GPU 性能。采样使用 `watchPerformance`，未启用真实音频引擎、DSP、真实封面解码或网络同步负载，也没有修改前的同机 FPS 基线。

| 指标 | 桌面布局 | 移动布局（Linux） |
| --- | ---: | ---: |
| 采样帧数 | 325 | 305 |
| 构建平均耗时 | 0.359 ms | 0.361 ms |
| 构建 P90 | 0.735 ms | 0.572 ms |

| 构建最大耗时 | 1.784 ms | 1.176 ms |
| 栅格化平均耗时 | 1.960 ms | 1.781 ms |

| 栅格化 P99 | 4.678 ms | 3.358 ms |
| 栅格化最大耗时 | 7.397 ms | 5.373 ms |
| 框架报告构建超预算帧数 | 0 | 0 |
| 框架报告栅格化超预算帧数 | 0 | 0 |

两个场景同时断言：滚动与进度更新期间没有再次读取 `displaySongs`。帧耗时不能直接换算成用户设备的实际显示 FPS，也不包含输入到屏幕呈现的完整延迟。

固定的统计摘要保存在 [ui-profile-2026-10-07.json](ui-profile-2026-10-07.json)。完整本机采样输出位于 `build/ui_performance/ui_performance.json`，重新运行时会覆盖。Linux 的 integration_test 原生插件报告了未检测到的提示，但 Flutter Driver 返回成功，回调已写入上述帧统计。

## 复测命令

在仓库根目录执行，确保 Flutter 已加入 PATH：

```sh
flutter analyze --no-pub
flutter test --no-pub
flutter drive -d linux --profile --driver test_driver/ui_performance_driver.dart --target integration_test/ui_performance_test.dart
```

普通应用构建使用 `flutter build linux --profile --target lib/main.dart`。性能测试会构建专用测试入口，测试产物不应作为普通应用分发。

真机复测重点：播放音乐时快速滚动与点击、DSP 开启后操作、抽屉和设置反复开关、长歌单搜索、不同大小封面的首次加载、键盘出现时菜单和底部面板的可操作性。Android 应以 Profile / Release 模式分别测量设备目标刷新率下的帧预算。

参考：[Flutter 性能实践](https://docs.flutter.dev/perf/best-practices)、[Flutter 性能分析](https://docs.flutter.dev/perf/ui-performance)。
